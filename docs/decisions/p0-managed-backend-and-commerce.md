# P0: bounded managed integration and provisional commerce

Accepted feasibility decisions, 7 October 2026; production metering and seller approval remain later external gates. All sources below were refreshed read-only. No account, payment, deployment or spending was initiated.

Keep Go for the offline execution core. Choose a small TypeScript Worker for future GitHub/billing integration: native supported WebCrypto, Request, D1 and scheduled runtime interfaces avoid Go/Wasm adaptation, a server fleet or a second terminal implementation. `scripts/feasibility` is a local synthetic probe only. Pin Wrangler 4.148.0 for reproduction; run `npx --yes wrangler@4.148.0 dev --local --config scripts/feasibility/wrangler.jsonc --persist-to .cache/worker-probe --port 8799` with metrics disabled. Its first task-date compatibility setting was rejected as future by the installed runtime; supported `2025-09-01` worked. This failure is preserved, not mistaken for an infrastructure outage.

Measured Windows local workerd: 191,915-byte/1,000-result JSON, HMAC sign/verify plus parse **5 ms wall**, RSA-2048 sign **7 ms wall**, D1 concurrent lease/index queries **71 ms wall**. Eight concurrent `UPDATE ... WHERE id=(SELECT ... LIMIT 1) RETURNING` claims returned eight distinct IDs. Indexed tenant query returned 20 rows; `EXPLAIN` used covering `jobs_tenant`. Synthetic delivery IDs insert once. Desktop Node complementary 100-iteration probe: CPU p50 0 ms, p95 16 ms, max 63 ms; RSS 56,942,592 bytes. Windows CPU timing is coarse, async crypto/library work can be accounted differently, and RSS belongs to Node, not a Worker isolate. Local elapsed/desktop CPU **are not Cloudflare CPU metering**. Key generation occurred outside measured operations; production key import/cold start and actual external API calls are still unproven. No deployed success is claimed.

[Workers limits](https://developers.cloudflare.com/workers/platform/limits/) currently include free 10 ms CPU/request, 100,000 requests/day and 128 MB memory. [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) lists free 5 million rows read/day, 100,000 rows written/day and 5 GB storage. Combined worst-operation local wall time leaves inadequate headroom to promise a single-request free path. Choose **separate durable receipt/parsing, cached token/signing and publication stages**, compact a production review manifest to 64 KiB with at most 1,000 compact result summaries, and keep raw/screens/full reports in GitHub. One staged task must target <=5 ms provider CPU p95, <=8 ms maximum before free-tier admission. Payloads above the declared production bound are rejected before parse; the 256 KiB local probe is a hostile upper envelope comparison. The free workflow context remains a separate 256 KiB customer artifact, not the paid ingestion API contract.

Durability design for P3: unique `(installation_id, delivery_id)` receipt, indexed `(state,due,lease)` jobs, atomic single-row lease and attempt increment, <=5 attempts within 15 minutes, crashed worker lease expiry, reconcile existing external check ID before retry publication, and terminal non-success on exhaustion. An acknowledgment follows durable insertion. Process <=8 jobs per scheduled invocation; rate-limit tenants before crypto/parsing, retain compact outcomes 30 days and delivery IDs seven days. Never depend on an unpersisted after-response promise. The probe proves local atomicity/index behavior; deployed contention, scheduled CPU accounting, backup/restore and remote fault behavior are gates before P5. A viable managed alternative if the free ceiling still fails is [paid Workers](https://developers.cloudflare.com/workers/platform/pricing/) at its published $5 minimum after a separately authorized revenue-funded budget; no upgrade was purchased. Free-tier production viability remains conditional, not zero-cost certainty.

Provisional first-sale route: **Paddle hosted merchant-of-record**, subject to actual approval; Marketplace becomes an adapter after eligibility. [Paddle pricing](https://www.paddle.com/pricing) is 5% + $0.50 with no monthly charge. [Seller country constraints](https://www.paddle.com/help/legal/sanctions/which-countries-are-supported-by-paddle) and [verification](https://www.paddle.com/help/start/account-verification/what-is-account-verification) require actual legal/product/identity review. Software subscription positioning is plausible; no seller jurisdiction, incorporation or bank facts are inferred from this user's timezone/account. Before P7 the owner must provide real eligible details to the provider and obtain approval; a hypothetical supported country is insufficient.

[Paddle customer portal](https://developer.paddle.com/concepts/sell/customer-portal/) supplies invoices/payment methods/subscription cancellation; [adjustments](https://developer.paddle.com/api-reference/adjustments/) support refunds, with provider approval/terms where applicable. Test sandbox cancellation, refunds, portal authorization and webhook reconciliation in P4. [Payouts](https://www.paddle.com/help/manage/get-paid/when-and-how-do-i-get-paid) have a minimum $100 threshold, monthly creation and sending by the 15th, with bank/FX/SWIFT costs potentially applicable. One $49 customer yields modeled $46.05 before refunds/tax/FX/operations, below the payout threshold; three monthly sales yield $138.15 before those adjustments. A $490 annual sale yields $465 under the same simple transaction formula, but capacity stays monthly and cash must cover the service term. Do not assume first-customer cash is immediately withdrawable.

[Marketplace requirements](https://docs.github.com/en/apps/github-marketplace/creating-apps-for-github-marketplace/requirements-for-listing-an-app) include verified organization and 100 App installations for paid listing; 100 operator-tested projects do not satisfy that. [GitHub payouts](https://docs.github.com/en/apps/github-marketplace/selling-your-app-on-github-marketplace/receiving-payment-for-app-purchases) describe 5% retention, $500 monthly threshold and following-month-end payment. GitHub provisions Actions runners for customer CI, not a subscription backend. [Developer agreement](https://docs.github.com/en/site-policy/github-terms/github-marketplace-developer-agreement) controls actual terms. Marketplace would net $46.55 at $49 before other obligations; threshold and seller approval remain constraints.

First-customer planned marginal metadata workload: 1,000 evaluations/month × at most 8 staged requests ≈8,000 requests/month plus bounded callbacks/settings/reconciliation. At 10 written/50 read rows per evaluation, model 10,000 writes/50,000 reads monthly plus retention. These are design envelopes, not measured cloud bills. API quotas, bursts, backfill, abusive unauthenticated traffic and support need explicit reserves. Alert at 60/80%; pause new work at 90% while preserving billing/deletion capacity. No hidden automatic overages. $49 minus processor costs is **not full profit**: infrastructure, taxes/refunds, support, maintenance and payout timing remain real costs. One $5 upgrade would leave $41.05 modeled before them, and requires available cash/approval.

Decision owners: maintainer for provider/cloud metering before P5, seller approval/legal terms before P7, pricing/unit economics after ten complete projects and before P7, and demand reassessment after launch. Revised engineering forecast: recorder/CI functionality can be delivered in a bounded batch, but cross-platform/hosted evidence and adversarial review take additional validation cycles. This batch does not validate low-maintenance operation, conversion, 100-project support, the paid App or automatic billing; their original later phase gates remain necessary.
